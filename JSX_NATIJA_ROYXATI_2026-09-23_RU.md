# Что урок (JSX) отдаёт в LMS при завершении — полный список

**Кому:** Шахзод (product manager) · Ахадулла (интеграция LMS) · Кристина (сервер)
**От кого:** команда дарс-платформы · 2026-09-23
**Основание:** код 97 уроков (`src/live/resultDetails.js`, `finishLesson`), 18 пакетов домашних заданий, формат `onFinished`, согласованный 2026-09-08 (ТЗ §4/§9)

> Коротко: при завершении урока в LMS через `onFinished` уходит **один JSON**. В нём есть каждый вопрос, каждое нажатие (попытка), время и достижения. Эти данные **уже сейчас** уходят — читать и сохранять их нужно на стороне LMS. Ниже: 1) все поля, которые уходят сейчас; 2) какую аналитику из них можно получить; 3) что есть в уроке, но пока не отправляется (добавим по запросу); 4) чего мы дать не можем — честно.

---

## 1. Поля, которые уходят в `onFinished` сейчас (урок)

### 1.1 Верхний уровень

| Поле | Значение |
|---|---|
| `lessonId` | Код урока с версией (`pm-m3d2-v3`) |
| `lessonTitle` | Название урока `{uz, ru}` |
| `lang` | На каком языке ученик прошёл урок: `uz` или `ru`. Все тексты ниже — на этом языке |
| `durationSec` | Время от открытия урока до завершения, в секундах |
| `totalQuestions` | Число зачётных тестовых вопросов (арена не входит) |
| `correctAnswers` | Сколько вопросов решено верно **с первой попытки** |
| `scorePercent` | `correctAnswers / totalQuestions`, в процентах |
| `finalScore`, `finalTotal` | Балл по итоговым (закрепляющим) вопросам |
| `passed` | Критерий балла: ≥60% итоговых вопросов верно с первой попытки. С 22.09 это **не** признак «урок завершён» — признаком завершения служит сам вызов `onFinished` |
| `questions[]` | Подробно по каждому вопросу (1.2) |
| `achievements[]` | Достижения, полученные в уроке (1.3) |
| `answers[]` | Сырые объекты ответов (1.4) — те же данные, что в `questions[]`, в старом формате; в части уроков содержат и артефакт мастерской |
| `nickname`, `livePin`, `liveMode` | Есть только в 27 уроках: имя в живом уроке, PIN и режим (`mentor` · `student` · `self`). В остальных 70 уроках нет — по запросу сделаем одинаково во всех |

### 1.2 `questions[]` — по каждому вопросу

| Поле | Значение |
|---|---|
| `question_id` | Стабильный код вопроса внутри урока (`s4`, `quiz-3`) |
| `kind` | `test` — входит в балл · `arena` — финальный бой (CodeStrike), в балл не входит, только в живом уроке |
| `order` | Порядковый номер в уроке |
| `question` | Текст вопроса (на языке ученика) |
| `options[]` | Тексты вариантов (≤6) |
| `correct_option`, `correct_answer` | Индекс и текст правильного варианта |
| `correct` | Верно **с первой попытки** |
| `solved` | Дошёл ли **в итоге** до правильного ответа (после любого числа попыток) |
| `attempts[]` | Каждое нажатие по порядку (≤10): |
| · `n` | номер попытки |
| · `option`, `answer` | индекс и текст выбранного варианта |
| · `correct` | верна ли эта попытка |
| · `elapsed_ms` | время от показа вопроса до нажатия, миллисекунды |
| · `at` | момент нажатия (UTC ISO) |

В живом уроке у каждого вопроса ровно одна попытка (`solved = correct`). В самостоятельном режиме ученик нажимает, пока не найдёт верный ответ — записываются все нажатия.

### 1.3 `achievements[]` — достижения

| Поле | Значение |
|---|---|
| `id` | Код достижения (`storybuilder`, `graduate` …) |
| `name` | Игровое имя (`Story Pro!`, `Level Up!`) |
| `title` | За что получено, на языке ученика («Вы написали 3/3 User Story в мастерской») |
| `earned_at` | Момент получения (UTC ISO) |

В каждом уроке 4 достижения, все — за **реальное** действие: первый верный ответ · артефакт мастерской · задание по коду · завершение урока (набор зависит от урока).

### 1.4 `answers[]` — сырые ответы (старый формат, сохранён)

Каждый элемент: `stage` (тип вопроса: `module-mikro` · `final` · `practice`), `screenIdx`, `question`, `options`, `correctIndex`, `correctAnswer`, `picked`, `studentAnswer`, `correct`, `firstAttemptCorrect`, `solved`, `lastPicked`.
На экране мастерской (practice): `practice` (название мастерской) и **`cards`** — артефакт, который написал ученик (например, тексты 3 User Story). Это есть не во всех уроках: в большинстве PM-уроков есть, в технических — реже.
Если ментор открыл ответ на доске до ответа ученика: `mentorRevealed: true`.

### 1.5 Пакет домашнего задания (18 шт.) — отдельный `onFinished`

| Поле | Значение |
|---|---|
| `lessonId` | Код пакета (`pm-m1-02`) |
| `kind` | `homework` |
| `done` | Выполнено ли (достаточно ли этапов) |
| `stages` | `"4/4"` — сколько этапов выполнено |
| `place` | Главный ответ ученика (например, строка КТО) |
| `durationSec` | Затраченное время |

Тексты внутри этапов (ответы из разговоров, вывод) сейчас не отправляются — можно добавить (раздел 3).

### 1.6 Напоминание: что уходит через School API (наш сервер, живые уроки из LMS)

Это отдельный канал, он уже работает: `student_id`, `correct_answers`, `answered`, `rank` (1–3), `badges[]` (`first_try`, `speedster`, `top_1..3`, `graduate`, `comeback`, `arena_top_N`, `participant`), `duration_sec`, `completed`. Изменений здесь не требуется.

## 2. Какую аналитику можно получить из этих полей (готовые формулы)

| Вопрос | Откуда берётся |
|---|---|
| Сколько раз ученик ошибся, прежде чем ответил верно? | `solved = true` и `correct = false` → число ошибок = `attempts.length − 1` |
| На каком вопросе класс ошибается чаще всего? | Доля `correct = false` по каждому вопросу (`question_id` стабилен — можно сравнивать между группами) |
| На какой неверный вариант нажимают чаще? | Распределение `attempts[].option`, кроме `correct_option` |
| Сколько думал над вопросом? | `attempts[0].elapsed_ms` (первое нажатие) · средний `elapsed_ms` |
| Угадывал ли (быстро и неверно)? | Малый `elapsed_ms` + `correct = false` |
| Сколько занял урок? | `durationSec` · интервалы между `attempts[].at` |
| Когда получил достижения? | `achievements[].earned_at` |
| Результат арены (боя)? | Вопросы с `kind = arena`: верно/неверно, время |
| Прошёл самостоятельно или в живом уроке? | `liveMode` (27 уроков) · либо `attempts.length > 1` означает самостоятельный режим |
| На каком языке учился? | `lang` |
| Что написал в артефакте? | `answers[].cards` (где есть) |
| Сделал ли домашнее задание, насколько? | `done`, `stages`, `place` |

## 4. Честные ограничения — чего дать не можем или что работает иначе

1. **О незавершившем ученике в `onFinished` ничего не уходит.** `onFinished` срабатывает только на последнем экране. Если ученик бросил урок на середине, LMS не получает ничего. Решение одно: если LMS будет принимать промежуточное событие (например `onProgress`), мы будем отправлять состояние на каждом экране. В текущем контракте такого события нет.
2. **Данные собираются в браузере.** История попыток хранится в `localStorage`; если ученик продолжит с другого компьютера, история прежних попыток потеряется (балл и `correct` сохраняются, `attempts[]` станет короче).
3. **`elapsed_ms` — от показа вопроса до нажатия.** Время, когда ученик переключился на другую вкладку, тоже входит. Это не «чистое время размышления».
4. **При повторном открытии в режиме просмотра `onFinished` может уйти ещё раз** (ровно тот же объект). Дубликат нужно отсекать на стороне LMS по `lessonId + ученик`; при желании мы заблокируем повторную отправку в завершённой попытке.
5. **Кто ученик — мы не знаем.** В JSX нет имени, группы, ID — их привязывает LMS.
6. **Арена записывается только в живом уроке.** В самостоятельном режиме арена — тренировка, её результат не уходит.
7. **Артефакты и рефлексия есть не в каждом уроке.** В технических уроках (HTML, JS, React, Node) мастерская — это код в компиляторе, а не текстовые карточки; там «артефактом» будет код (пункт 5 раздела 3).
8. **Данные — только о том, что происходит внутри урока.** Мы не видим, что ученик делал в LMS до и после урока, сколько раз открывал страницу, с какого устройства заходил.
9. **Никакого звука, камеры, записи экрана нет и не будет.**
10. **Максимумы формата (согласованы 08.09):** ≤200 вопросов, ≤10 попыток на вопрос, ≤6 вариантов, ≤300 символов на текст, ≤20 достижений. Больше не храним.
